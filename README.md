# API Testing Agent

Терминальное приложение для функционального тестирования REST API по спецификации OpenAPI. Локальная языковая модель выполняет цель на естественном языке. Команды модели исполняются в изолированном Docker worker, а приложение разрешает только настроенные операции целевого API. Результаты, HTTP-трасса и отчёты хранятся локально.

В режиме **Исследование** агент работает с целью без пользовательских проверок. В режиме **Тестирование** приложение также проверяет условия, выбранные в конструкторе.

## Требования

- Windows x64, Git и Python 3.11 или 3.12.
- Запущенный Docker Desktop в режиме Linux containers.
- Терминал с поддержкой Unicode, например Windows Terminal.
- Локальный HTTP-сервер llama-server с поддержкой шаблона чата и токенизации либо совместимый llama-server и модель GGUF.
- Доступный тестовый REST API и его спецификация OpenAPI 3 в JSON.

## Установка

```powershell
git clone https://github.com/ProkIlya/RT5-81-Prokofev-Ilya-VKR.git
cd RT5-81-Prokofev-Ilya-VKR
py -3.11 setup.py --prepare
.\.venv\Scripts\python.exe main.py --tui --state .api-agent/ui.sqlite3
```

Если установлен Python 3.12, используйте `py -3.12` в команде установки. Установщик создаёт `.venv`, устанавливает закреплённые зависимости и собирает Docker worker. Для первой установки нужен доступ к реестру Docker и Python-пакетам. Модель и тестовый API подготавливаются отдельно.

## Первый запуск

1. В настройках добавьте адрес локального сервера модели или выберите файл GGUF и исполняемый файл llama-server.
2. Создайте проект с адресом API, файлом OpenAPI и разрешёнными операциями. При необходимости настройте вход.
3. Откройте сессию, введите цель и отправьте её клавишей **F5**. **F3** открывает инспектор HTTP, **F2** — навигацию, **Ctrl+Q** завершает работу.

В примере состояние хранится в `.api-agent/ui.sqlite3`. Диагностика доступна в настройках приложения. Для отдельного запуска используйте `main.py --tui --state <путь>`.
